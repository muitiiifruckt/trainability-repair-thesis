# Предложение следующей кампании (не запущено, не заморожено)

Статус: проект дизайна от 2026-10-09 по итогам дебата A/B2 (`research/debate/log.md`) и первых 40 исходов screen. Текущая кампания `minatar-repair-20261007` не меняется; новая использует **новый `output_root`** и новые SHA кода. Числа ниже — из перечисленных файлов; оценки стоимости помечены.

## Зачем
Текущий screen (2 игры x 3 seeds x 2 возраста x 4 действия x 2 repeats) по расчётам B2 не даёт ни положительного, ни отрицательного вердикта о пользе диагностик: n=12 историй даёт мощность «информативности» ~28% при сильном сигнале (b=0.8), n=24 — ~75%; отрицательный вердикт допустим только при n>=24 (log.md, вход 4). Кроме того, возраст неотделим от epsilon/replay при двух возрастах (corr = ±1).

## Что менять (каждое со ссылкой на обоснование)
1. **Repeats 4 вместо 2** — относительная мощность +~50% (B2 вход 4); шум одной ветки SE 0.6–1.9 (`scripts/debate_noise_floor.py`).
2. **Финальная точка >=100–200 eval-эпизодов вместо 20** — стоит <1% времени ветки (eval 7–15 мс на эпизод против 344–632 с на ветку; B2 E6); SE среднего 200 эпизодов: 0.10–0.13 (50k) / 0.20–0.36 (200k).
3. **Третий возраст 25k** (между 5k и 100k eps/replay меняются независимо от возраста, выше 105k они насыщены; B2-3): разделяет «возраст» от «epsilon/заполнения replay».
4. **Arms для атрибуции вреда головы** (A, раунд 2): continue; head_reset (stale target); head_reset_sync как контроль; fresh_head_reset; injection (`rl_core.py`); split-Adam reset state:head и state:body (`scripts/debate_split_adam.py`, нужна обёртка вне замороженных модулей). Вред головы = head_reset − injection; sync — контроль, не причина.
5. **Baseline «текущее качество» включает `j_pre`** (greedy-оценка до вмешательства, `checkpoints.jsonl`), а не только ε-greedy `recent_return_mean` (внутри 50k corr с настоящим качеством −0.84 против +1.00; B2 вход 4 п.6).
5б. **Диагностики усреднять по K=30 батчам** (B2 вход 6, `research/debate/b2_diag_noise.json`): надёжность одного замера `pre_td_huber` всего 0.47 (cv 0.21), у `gradient_m_cosine` sd измерения до 0.445 (знак не определён), тогда как `feature_entropy`/`dormant_fraction`/`m_norm`/`sqrt_v_norm` измеряются практически без шума. Усреднение по 30 батчам стоит ~2.2 с на checkpoint и поднимает надёжность `pre_td_huber` до ~0.9. Хранимый `diagnostics.jsonl` текущей кампании — одна реализация; не менять, пересчитывать отдельно из артефактов с проверкой sha.
6. **Prereg v3 заранее фиксирует** comparator, двухуровневый вердикт («информативно» / «практически полезно»), z-score и перестановки внутри игры (Freedman–Lane, ранги D и y), reliability gate (ICC эффекта по repeat) до диагностического теста, усреднение по всем завершённым repeat; ворота ложных negative <=0.10. Файл — `research/debate/prereg_diag_sign.md` (A финализирует).
7. **Единица независимости — история**; интервалы только при >=5 историй, лучше t или sign-flip по историям (реальное покрытие процентильного bootstrap 0.44/0.71/0.84/0.89/0.89/0.94 при 1/2/3/5/6/12 историях).
8. **Исправления генератора** (в новой кампании, не в текущей): проверка `small_history_count` перед печатью `ci95` (`rl_runner.py:519`), не стирать ручные заметки, `replace` с повторами для savepoint на OneDrive (`rl_runner.py:86-91, 207-217`), `fsync`/устойчивое чтение хвоста JSONL, whitelist признаков (`research/debate/patch_whitelist.diff`).

9. **Дополнения B2 (вход 10):** arm с distillation-warmup для головы, горизонт >=100k на возрасте 200k (50k может быть слишком коротким для восстановления после head reset: просадка в 200k больше, −5.35/−6.2 против −1.4/−1.7 на 50k, `research/debate/cost_decomp.json`), >=6 checkpoint на возраст.

10. **Почему сброс Adam не помог (гипотезы H-eps, H-timing в `research/NEXT.md`):** arms `optimizer_reset` с ε = 1.5e-4 (как у Rainbow/Asadi) и с коротким LR-warmup; сброс в момент обновления target; логирование ‖Δθ‖/‖θ‖ первых шагов после сброса. Источник идеи — сравнение с Asadi et al. 2023 и Lyle et al. 2023 §4.1 (в DQN обычно берут большой ε).

## Масштаб и стоимость (оценка)
Медиана ветки 396 с (IQR 376–447, 38 из 40 строк < 1000 с; остальные содержат сон машины), два workers параллельно -> ~200 с на ветку. Этап «репликация»: 12 историй (6 на игру) x 3 возраста x 4 arms x 4 repeats = 576 веток ≈ 32 ч вычислений; с учётом ночных снов 9–10 ч (кампания не считается) — ориентировочно 2.5–3 календарных суток. Стоимость обучения исходных историй до 200k шагов в этой оценке **не пересчитывалась** — измерить по manifest перед запуском. Расширенные arms (п.4) — отдельный, меньший этап на выбранных checkpoint.

## Условия запуска (не раньше)
- Завершён текущий screen и `primary_gate` определён; результат использован для решения, нужна ли репликация (если `single_repair` с ясным победителем — иная постановка).
- Prereg v3 заморожен до просмотра данных новой кампании; A/B2 согласовали dry-run (ложные положительные <= ~2.5–3%, `null_hetero_coupled`).
- Решение пользователя о режиме питания (сон останавливает кампанию).
- Reserved-игры (freeway, seaquest) остаются закрытыми до freeze протокола.

## Риски
Сильный сигнал диагностик априори маловероятен (Lyle 2023/2024, He 2026 по аннотации; B2 вход 5), реалистичны b<=0.4–0.8 — именно там мощность мала; negative при n=12 — «оценщик не извлёк», не «диагностика бесполезна». Возможный исход проекта — характеризованная гетерогенность откликов без полезного селектора; это допустимый результат (решение 10 от 2026-10-05).
