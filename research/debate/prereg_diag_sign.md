# Pre-registered план: добавляет ли pre-repair диагностика пользу при выборе head/optimizer reset

Статус: написано 2026-10-09 ДО анализа каких-либо исходов по diagnostics (в `outcomes.jsonl` на момент записи 16 строк = 1 история, breakout seed0; по ней анализ не делался). Автор: A (Proposer). Ждёт замечаний B. После согласования файл не редактируется; поправки — только отдельным разделом «Отклонения» с датой.
Проверка самой процедуры на синтетике: `scripts/debate_prereg_dryrun.py` -> `research/debate/prereg_dryrun_n*.json`.

## 1. Единицы и данные
- Единица независимости, split и bootstrap: `trajectory_id` (полная исходная история). Строки анализа: (history, nominal_age); оба возраста одной истории всегда вместе в одном fold. Repeats внутри (history, age) усредняются до анализа.
- Только завершённые парные ячейки (все 4 действия, оба нужных repeat; `failure_reason` пуст). Reserved-игры (freeway, seaquest) не используются. Анализ запускается один раз на зафиксированном срезе `outcomes.jsonl` (SHA256 среза записывается в результат); пересчёты на более поздних срезах помечаются как новые, не заменяют первый.
- Минимум для любого утверждения «положительно/отрицательно»: >= 12 историй суммарно и >= 5 на игру. Меньше — вердикт «неопределённо» без отчёта точечной оценки как результата.

## 2. Цели (target) и множественность
Две первичные цели, α делится поровну (Bonferroni, α = 0.025 на цель, односторонний тест на «польза > 0»):
- T-head: y = j_final(head_reset) − j_final(continue);
- T-opt: y = j_final(optimizer_reset) − j_final(continue).
`head_and_optimizer_reset` и interaction — вторичные, описательные, без вердикта.
Масштаб: y делится на sd возвратов эпизодов continue той же игры (по всем её завершённым continue-ветвям; не зависит от действия). Тем самым игры сопоставимы (замечание B п.6).

## 3. Признаки (только whitelist)
Допустимы ровно эти поля из `diagnostics.jsonl`/метаданных checkpoint, измеренные ДО вмешательства:
- `pre_td_huber` (pre-repair TD loss), `recent_return_mean` (recent return);
- clock-признаки: `nominal_age`, epsilon в checkpoint (выводится из `environment_steps` по формуле конфига: 1 − 0.9·clip((steps − 5000)/100000, 0, 1) — перепроверить по `rl_core.py` до запуска), `replay_size`. Они функции одного `environment_steps` и сильно коллинеарны; в модель входит один clock-признак — `nominal_age`; epsilon и replay_size используются ТОЛЬКО в защитной проверке п.7.3.
Запрещены как признаки: `j_immediate`, любые поля outcomes (post-repair), `weight_norm`, `q_abs_max`, `target_abs_max` (кодируют игру), `optimizer_age_*`, `gradient_updates`, `target_age_updates`, любые не из списка (чёрные списки не используются).
Остальные диагностики (gradient_m_cosine, feature_entropy…, dormant_fraction…, m_norm, sqrt_v_norm) — эксплоративные, отдельная таблица, без вердикта.

## 4. Модели и baseline
Все модели — ridge (α_ridge = 1.0, зафиксировано, не подбирается) на z-score признаков (mean/sd по обучающим историям fold'а), intercept не штрафуется, предсказывается y.
- `age_only`: [nominal_age]
- `diag_only` (baseline B1): [pre_td_huber, recent_return_mean]
- `all` (кандидат): [nominal_age, pre_td_huber, recent_return_mean]
- `const`: знак среднего y по обучающим историям (всегда repair/всегда continue);
- `continue`: всегда continue (utility 0).
Правило: repair, если предсказанный эффект > 0, иначе continue.

## 5. Валидация и метрика
Leave-one-history-out (LOHO). Utility истории = среднее по её строкам реализованного эффекта выбранного правила (y, если repair; 0, если continue). Utility модели = среднее по историям. Лучший baseline = argmax utility среди {age_only, diag_only, const, continue} на этих же данных (консервативно: выбор «в hindsight» в пользу baseline).
Δ_h = utility_h(all) − utility_h(лучший baseline); статистика = mean_h Δ_h.

## 6. Критерий «диагностика добавляет пользу» (для цели, независимо по T-head, T-opt)
Все условия одновременно:
1. mean Δ > 0;
2. перестановочный тест: столбцы diag (pre_td_huber, recent_return_mean) переставляются между историями целиком (оба возраста вместе), 99 перестановок, лучший baseline перевыбирается в каждой; p = (k+1)/100 < 0.025;
3. bootstrap по историям (1000 ресэмплов) 2.5%-квантиль mean Δ > 0;
4. n_историй >= 12 (п.1).
Минимально значимая практическая величина δ = 0.2 sd игры на историю (в единицах п.2).

## 7. Что считается отрицательным результатом и защитные проверки
7.1 Отрицательный: n >= 12 и верхняя граница bootstrap 97.5% mean Δ < δ = 0.2 -> «диагностика (в этом whitelist) не добавляет практической пользы сверх age/loss+return baseline на данном срезе»; это публикуется на равных с положительным.
7.2 Всё остальное (в т.ч. LB <= 0 < UB) — «неопределённо», с планом расширения (source seeds 3,4,5 по research_program).
7.3 Защитная проверка clock: повторить анализ, подставив вместо `nominal_age` пару [epsilon, replay_size]; положительный вердикт засчитывается только если он сохраняется в обоих вариантах. Если Δ исчезает — эффект приписывается clock/exploration, не диагностике.
7.4 Leave-one-game-out не планируется (2 игры, недостаточно) — вердикт относится только к breakout/asterix.
7.5 Повторное использование среза: любые решения по результатам (выбор признаков, α) на этом же срезе запрещены; новый срез — новый запуск с тем же планом.

## 8. Проверка процедуры (dry run)
`scripts/debate_prereg_dryrun.py` моделирует: null, null с высокой внутри-историческим random effect (ICC), signal только по age, signal по age + диагностика, коррелированная с age (confound rho=0.7), смещение по играм, настоящий diag-сигнал (сильный и слабый). 200 симуляций на сценарий; критерий — доля положительных вердиктов. Допустимо: ложноположительная доля в null/confound сценариях <= ~α (0.025 + MC-ошибка при 200 симуляциях: до ~0.06 не противоречит). Результаты — раздел ниже (заполняется по факту).

## 9. Известные ограничения плана
- 12 историй — это мало: мощность на слабом сигнале низкая (см. dry run); отрицательный результат без δ-границы не интерпретируется.
- y содержит шум оценки возврата (SE 0.6–1.9 на ветку при 20 эпизодах, `scripts/debate_noise_floor.py`) и траекторный шум; повторы одной истории не независимы.
- Оценка выбора по знаку эффекта не равна оценке «значимо вредящего» repair; утилита — средняя по истории реализованная.
