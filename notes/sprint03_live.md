# Sprint 03: предрегистрация живых S3/S4

Дата: 2026-11-09. Протокол фиксируется до любых новых научных запусков.
Основание: `sprint03_criteria.md`, `ppo_probe.md`, план Sprint 03, замечания руководителя 25.10.
Новый output_root: `runs/causal-trainability/sprint03_live_20261109/`.
Это малый gate различимости ремонтов и контролей переноса, не обучение selector и не validation лабораторной метрики v2. Метрика v2 здесь не разрабатывается. Уже просмотрены T7 и offline v2; это follow-up на тех же историях, не перенос на независимые histories.

## Дизайн

Breakout `cnn`, 6 исходных histories s0–s5. Source — те же концы `actions_chain` (2M суммарных шагов), переход round4→round5. Настройки PPO неизменны. Бюджет каждой ветки 500000 номинальных env steps (499712 фактических, 488 полных rollout по1024), одинаковый для всех. Семена среды/обучения namespace `deficit`, как в T7; все исходы пересчитываются в новом root, старые исходы не подмешиваются. Старт и финал: 100 эпизодов на общих seeds, отдельный evaluation RNG. Анализ по 6 histories, повторы не независимы.

S4: 4 повтора × 3 действия `continue`, `adam_reset` (все веса прежние, Adam пустой), `heads_reset` (actor/critic из θ₀, Adam головы пустой, тело и его Adam прежние). 72 ветки.

S3: общие с S4 `heads_reset` repeats0–1 плюс 2 повтора каждого `fresh`, `heads_fresh_adam` (те же сброшенные головы, весь Adam пустой), `inverse` (сохранение физической стартовой политики через перестановку actor и соответствующих Adam moments). Ещё 36 веток, всего108. θ₀ берётся из source каждой истории, без новой случайной инициализации. Inverse row j = inv(old_perm)[new_perm[j]]; переставляются actor weight/bias, exp_avg/exp_avg_sq, не scalar step. Сохраняются распределения физических действий, не побитовая траектория categorical sampling.

## Исходы и правила

S4 primary: средний episodic return в10 равных окнах фактического бюджета; затем среднее10 окон. Пустое окно делает анализ невалидным, не выбрасывается. Для каждого ремонта d_ir=repair−continue на повторе; d_i=mean4(d_ir). W=sqrt(mean_i var_r(d_ir,ddof1)). Устойчивое различие: family95 Bonferroni (два97.5% t-интервала, df5) исключает0; все6 d_i одного строгого знака; |mean d_i|>W. Устойчивый отрицательный эффект также записывается. Финальный return — secondary без отдельного подтверждающего вердикта.

Checkpoint chooser выбирает среди3 действий по mean repeats0–1 на каждой истории. Постоянный ремонт выбирается по среднему тех же repeats0–1 всех histories. Оба оцениваются только по2–3; ties в порядке continue→Adam→heads. Gain g_i, среднее и95% tCI(df5) по6 histories. Продолжать к правилу выбора можно лишь при lowerCI>0 и хотя бы одном устойчивом repair-контрасте. Иначе operational stop по S0: преимущество выбора не показано. Это не доказательство нулевого эффекта или принципиальной невозможности выбора. Подбор по heldout исходам запрещён.

S3 primary: среднее последних5 training windows; отдельно полный AUC, финальный return и стартовый return. Сравнения heads_reset/fresh и heads_fresh_adam/fresh описываются парными history-level difference. Критерий «медленнее при сопоставимом старте»: верхняя граница97.5%CI(df5, два reset/fresh контраста) ниже0; отрицательный знак минимум5/6 histories; модуль среднего превышает W парных разностей на2 repeats; gate сопоставимости пройден. Inverse/fresh и вторичные исходы описательные,95% CI без формального механистического вердикта. Этот критерий не равнозначен доказанной потере обучаемости. Нормы/энтропия/V не называются доказанными причинами.

Gate сопоставимости для каждой reset-heads ветки: на одном фиксированном reference-батче TV(policy,fresh)<=.02; |mean entropy difference|<=.02nats; RMS(V−Vfresh)<=.1 raw value units во всех6 histories и2 repeats. Дополнительно90% tCI по6 средним парным разностям стартового return целиком в[-.1,+.1] raw return. Это строгие операционные допуски, научная универсальность не заявляется. Порог не смягчается после просмотра. Если gate не пройден, объяснение «обучаемость против переноса» остаётся неопределённым. Даже если gate пройден, медленное обучение старого тела при fresh Adam требует согласия с отдельной офлайн-пробой; само по себе не доказывает потерю обучаемости. Перенос тела и будущая occupancy могут различаться. Офлайн v3 — follow-up, а не независимая confirmation.

## Наблюдаемость и остановка

Все ветки: штатная layer-wise L2/Adam каждые16 итераций (≈16k env steps; выбор частоты до научных исходов для снижения overhead); L3 в0/10/25/50/75/100% бюджета; θ₀; source/chain sha256, settings, code hashes, seeds, окружение, полная training curve. Eval использует собственный RNG. Unit tests проверяют interventions, физическую policy equivalence inverse, state ownership и невлияние logging. До полной серии прогретый свободный от параллельного обучения timing pilot: mean и median overhead<=5% в обеих ячейках continue и heads_reset, weights/Adam bit equal. Код, предрегистрация и очередь фиксируются manifest; изменение требует нового output_root. Незавершённый attempt сохраняется, повтор запускается в новой папке с теми же seeds. Максимум2 workers по1 torch thread. Файл STOP в корне очереди запрещает новые ветки, текущие заканчиваются. Ошибка останавливает очередь, исход не подменяется отрицательным результатом.

Возрастной контроль2M без смен — optional, не включён в108 веток; возраст и число смен остаются смешаны. Содержательная смена условий пока не запускается: план требует согласования вида с руководителем. Подготовка предложения не считается выполнением этого пункта. До решения по S3/S4 новых больших серий и selector нет.
