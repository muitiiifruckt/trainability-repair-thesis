# Данные, occupancy и выбор вмешательства

Дата проверки: 5 октября 2026. Это рабочая заметка по первичным источникам, а не исчерпывающий systematic review. `full_text` в библиографии означает, что были открыты и проверены относящиеся к вопросу разделы полного текста; это не заявление о построчном прочтении всех приложений. Свежие arXiv-работы отделены от опубликованных. Собственные предложения ниже помечены явно.

## Главный вывод для позиционирования

Связка «измеряем состояние сети → адаптивно вмешиваемся» уже существует. Особенно близки Adaptive RR, Automatic Soft Reset, SNR, CPR и NeuMoSync. Поэтому широкая формулировка «первый diagnostic-driven repair» не защищена. В найденных работах не обнаружен точный эквивалент **обучаемого выбора между разными классами вмешательств — weights / optimizer / data / targets — по диагностике исходного checkpoint, с метками от контролируемых копий и оценкой regret на полностью отложенных средах**. Это ограниченный результат поиска, а не доказательство отсутствия prior art.

## Что дают проверенные работы

**1. Primacy Bias — Nikishin et al., ICML 2022.** В high-replay regime ранние данные могут надолго ухудшать обучение. Авторы периодически сбрасывают параметры, сохраняя replay buffer; очистка самого buffer существенно мешает восстановлению. Appendix B также проверяет optimizer state. Это сильная исходная точка для эксперимента «одни накопленные данные, разные состояния learner». Но эффективность reset ещё не устанавливает единственную причину: после него меняется policy и будущий поток опыта. [Статья, §§4–5 и Appendix B](https://proceedings.mlr.press/v162/nikishin22a/nikishin22a.pdf).

**2. Revisiting Plasticity / Adaptive RR — Ma et al., ICLR 2024.** Авторы исследуют augmentation, actor/critic/encoder и стадии обучения. Они используют critic FAU для переключения replay ratio с низкого на высокий после стабилизации активности. В DMC описано переключение 0.5→2 при изменении FAU менее 0.001; есть Atari-100k evaluation. Это прямой prior для diagnostics→adaptive intervention, но controller задаётся правилом и регулирует один training knob. В статье также используется factorial DA×reset анализ. [Полный текст, §§3–6, Appendix C](https://proceedings.iclr.cc/paper_files/paper/2024/file/5647763d4245b23e6a1cb0a8947b38c9-Paper-Conference.pdf).

**3. Dissecting Deep RL with High Update Ratios — Hussing et al., RLJ/RLC 2024.** Здесь часть явлений primacy объясняется Q-value divergence: OOD action predictions и Adam momentum усиливают проблему; output feature normalization помогает при высоком UTD. Actor-reset ablation показывает, что устранение critic divergence не объясняет все ограничения. Для нашего проекта это особенно полезное предостережение: high replay ratio может создавать смешанный failure mode, в котором участвуют optimizer, values и поведение. [Полный текст, §§3–5](https://arxiv.org/html/2403.05996).

**4. ROER — Li et al., RLJ/RLC 2024.** Replay prioritization выводится из occupancy optimization с f-divergence regularization; TD-error-based ratios меняют эффективное распределение обучающих переходов. Проверки включают SAC на continuous control и offline-to-online AntMaze. Это кандидат для practically available data intervention, но работа не занимается диагностикой plasticity или выбором repair. TD error одновременно определяется learner и targets, поэтому его нельзя считать независимой характеристикой качества данных. [Полный текст](https://arxiv.org/html/2407.03995), [официальная публикация](https://rlj.cs.umass.edu/2024/papers/Paper198.html).

**5. Automatic Soft Parameter Reset — Galashov et al., NeurIPS 2024.** Параметры связываются OU drift model; величина возврата к initialization и изменения learning rate обучается по predictive likelihood. В RL drift оценивается на свежих chunks опыта, затем используется при replay updates. Это более сильный prior, чем фиксированный reset schedule: метод действительно учит интенсивность вмешательства из данных. Однако выбирается одна семья soft parameter updates, а не дискретный heterogeneous repair menu. RL evaluation ограничена Hopper/Humanoid и тремя seeds. [Полный текст, §§3, 5.1](https://arxiv.org/html/2411.04034v1).

**6. Self-Normalized Resets — Farias & Jozefiak, ICLR 2025.** SNR решает, когда сбрасывать neuron, через тест нулевой firing rate; threshold использует историю межактивационных интервалов. Показаны преимущества на continual supervised learning и устойчивость к rejection percentile. Это prior для более принципиальной диагностики и reset timing. Но это не multi-repair RL selector: экспериментальная часть в основном supervised CL. Нельзя переносить статистическую обоснованность теста firing на корректную идентификацию причин RL stagnation. [Полный текст, §2 и experiments](https://arxiv.org/html/2410.20098v2).

**7. AdaLin — Rohani et al., first release 2025.** Каждый neuron учит величину linearity injection, а gate зависит от derivative базовой activation. Это continuous adaptive intervention без task boundaries. В arXiv v1 есть SAC experiments с разными replay ratios; это важно как baseline адаптивного поддержания plasticity. Есть библиографическое расхождение: arXiv указывает CoLLAs 2025, текущая PMLR страница — proceedings year 2026. RL выводы здесь относятся именно к проверенной arXiv v1. [arXiv, §§2, 3.6, Appendix D](https://arxiv.org/html/2505.09486v1), [PMLR metadata](https://proceedings.mlr.press/v330/rohani26a.html).

**8. ReSiN — He & Liu, arXiv 2025, revised July 2026.** Текущая v4 называется *Silent Neuron Theory and Plasticity Preservation for Deep Reinforcement Learning in Adaptive Video Streaming*. Silent criterion совмещает малые forward outputs и backward gradients, определяя координаты selective perturbation/reset в PPO. Работа показывает, почему dormant ratio сам по себе может ошибаться: больше dormancy совместимо с лучшим результатом. Область проверки — adaptive video streaming; это не доказательство универсального диагностического критерия для RL. [Полный текст, §§IV–V](https://arxiv.org/html/2505.01584).

**9. CPR — McCutcheon et al., arXiv July 2026.** Calibrated Partial Resets оценивает utility по норме incoming gradients, нормирует и сглаживает её, затем задаёт каждому neuron силу частичного возврата к initialization. Проверены SlipperyAnt/Humanoid, Continual MetaWorld/MinAtar. Авторы прямо разделяют «какие units менять» и «насколько сильно». Это очень свежий prior для diagnostic-dependent repair intensity. Но mapping задан конструкцией метода и hyperparameters; learned choice между optimizer/data/targets repairs не исследуется. [Полный текст, §§3–5](https://arxiv.org/html/2607.24996v1).

**10. NeuMoSync — Rohani et al., arXiv August 2026.** Learned global controller получает текущий input и neuron features/history; выдаёт четыре коэффициента, управляющие weight mixture, consolidation, linearity и offset. В оценке используются snapshot copies и дообучение фиксированным малым числом batches на новых/старых задачах. Это важнейший свежий prior к «learned plasticity control» и fixed-budget adaptation evaluation. Проверены supervised CL benchmarks; controller не выбирает checkpoint repairs из нашего меню и не оценивается как selector на held-out RL environments. [Полный текст, §§2–3](https://arxiv.org/html/2608.04358v1).

Дополнительная близкая зацепка: **Plasticity Injection (NeurIPS 2023)** обсуждает adaptive criterion для времени injection в Appendix B; поэтому diagnostic-based timing одного parameter repair тоже нельзя считать новым. [Полный текст](https://papers.neurips.cc/paper_files/paper/2023/file/75101364dc3aa7772d27528ea504472b-Paper-Conference.pdf).

## Как учитывать данные в нашем эксперименте — предложения проекта

Occupancy — распределение посещаемых state-action pairs. В online RL оно зависит от policy, а policy зависит от сети, optimizer и targets. Поэтому «на фиксированном batch всё нормально, live RL плохо» локализует проблему обратной связи, но не доказывает, что испорчены только данные. Reset critic может улучшить действия через value estimates; reset actor может лишь заставить исследовать новые состояния. У intervention есть прямой эффект на learner и опосредованный эффект через последующий опыт. Эти эффекты надо оценивать отдельно.

Предлагается два уровня проверки. **Replay experiment**: все копии получают один заранее записанный поток minibatches. Для tests на trainability targets также замораживаются либо задаются внешним teacher; просто общий replay не делает targets одинаковыми. **Closed-loop experiment**: каждое вмешательство продолжает собирать собственный опыт, но с одинаковым разрешённым interaction budget. Первый оценивает conditional learner response; второй — полезность полного repair в системе. Для репозитория стоит сохранять оба outcomes и не сводить их в один «истинный тип деградации».

Data repair необходимо операционализировать. Например: изменить sampling mixture старых/свежих переходов; включить fixed augmentation; добавить порцию опыта от сохранённой reference policy; разрешить небольшой exploration burst. У этих действий разная доступность и цена. Expert buffer без оплаченного сбора — privileged oracle intervention, а не доступный production repair. Смена replay ratio меняет число updates: при фиксированном числе шагов optimizer она не эквивалентна прежнему сравнению. Нужно заранее задать budget vector `(environment transitions, gradient updates, diagnostic compute)` и сравнивать действия при одной его границе.

Для диагностики полезно хранить две версии neuron statistics: на текущем occupancy/replay и на общем reference probe set. Низкий FAU только на текущих состояниях может отражать узкий visitation support; низкий FAU на reference probe расширяет основания подозревать сеть. Ни один из этих вариантов сам по себе не устанавливает causal root cause. Аналогично policy entropy надо читать вместе с coverage: уверенная хорошая policy тоже имеет низкую entropy. Coverage proxy может быть state bins для небольшого стенда либо distances в заранее фиксированном representation, а не embedding, который сам меняется после repair.

Для первого selector проще сохранять в labels весь вектор оценок `Y_i(a)`, включая continue, чем noisy argmax label. Тогда можно учить outcome/ranking model и выбрать действие с максимальным прогнозом. Regret должен штрафовать величину потерянного gain, а не только несовпадение названия repair. Если reset и continue статистически близки, формальное «не угадал argmax» мало значит. Повторные adaptation seeds нужны и для uncertainty outcomes, и для оценки оптимизма sampled oracle; нельзя оценивать oracle только по максимальному из одиночных шумных запусков.

Самый сильный feasibility gate: показать effect heterogeneity. На группе checkpoints должны существовать состояния, где optimizer reset лучше parameter reset, и наоборот; data/target repair должен выигрывать хотя бы в части случаев. Если один repair практически всегда лучший, learned selector не нужен, даже если метрики красиво коррелируют с временем обучения. Следующий gate — превзойти простое правило из одного-двух signals и лучшую постоянную intervention, выбранную только на train environments.

Held-out evaluation надо строить по environment families/MDP, а не случайно перемешанным checkpoints. Seeds и соседние checkpoints одного run сильно зависимы; иначе selector может выучить env identity и training age. Отдельные уровни сложности: unseen seeds, unseen checkpoint age, unseen tasks внутри семейства, unseen environment family. Во всех случаях diagnostics вычисляются до repairs; feature normalization, threshold tuning и выбор лучшего постоянного repair обучаются без test outcomes.

Итоговое рабочее позиционирование: **полезность и переносимость диагностики для выбора доступного вмешательства при ограниченном бюджете**, с контролируемыми comparisons и uncertainty-aware regret. «Четыре независимые причины» лучше оставить гипотезами модели эксперимента, а не обещанным результатом.
