# Спринт 04: протокол технического пилота

Зафиксирован до запусков, 2026-11-13. Это проверка реализации и наблюдаемости, без научного сравнения return и без интервалов эффекта.

## Дизайн

Только development-истории Breakout cnn s0/s1. Два тела: исходная θ⁰ и конец actions_chain той же истории. Actor и critic полностью обнуляются в обеих ветках, Adam свежий. Сохраняется перестановка round 4 из chain; содержательная смена — sticky probability 0.1 → 0.25. Параметры PPO из исходного checkpoint; 64 итерации по 1024 перехода. Один CPU worker, один torch thread. Output root `runs/causal-trainability/sprint04_pilot_20261113`.

Env/PPO seeds зависят только от истории с namespace s04-tech, общие для тел. Проверки: нулевые начальные logits и value на reference, одинаковые первые rollouts и RNG генератора. Первый minibatch должен иметь нулевой градиент тела; следующие градиенты регистрируются по слоям. Выходы после первого обновления могут расходиться из-за признаков: это ожидаемое свойство дизайна, не ошибка и не критерий дефицита.

## Наблюдаемость и технические критерии

Сохраняются SHA кода, протокола, config, seeds, источников, θ⁰, reference, первого rollout, L3 на 0/32/64, полный checkpoint перед последним обновлением, по слоям L2 и Adam каждые 16 итераций, начальная L2-строка, градиенты первых двух minibatches. Чекпоинт проверяется продолжением последнего обновления до побитового совпадения weights/Adam/PPO RNG.

Для s0: прогрев обоих режимов по 4 итерации и три последовательные пары telemetry on/off на каждое тело в порядке on/off, off/on, on/off. Для s1 — одна пара на тело для проверки воспроизводимости; время s1 не используется как калибровка overhead. Проверяются равенство конечных weights/Adam, глобального torch RNG и PPO RNG с логированием и без. Режим off — исключительно технический контроль телеметрии; его checkpoints и manifest сохраняются.

PASS: начальные выходы нулевые; первые rollouts совпали; первый градиент тела нулевой; checkpoint resume и logging on/off побитово совпали; для каждого тела s0 mean и median overhead ≤5%. Время измеряется от начальной телеметрии до закрытия её writer и сохранения финальных артефактов. Случайный отрицательный overhead не трактуется как ускорение. При FAIL научная очередь не запускается, допуски не ослабляются задним числом. Изменение реализации требует новой версии и output root.

## Научный исход

Этот пилот не оценивает потерю обучаемости. Return не служит основанием выбора горизонта, seeds или следующего эксперимента. Дизайн научного сравнения, его основной исход, порог практически значимого эффекта и объём будут записаны отдельно после технического решения; научные серии данным протоколом не разрешаются.
