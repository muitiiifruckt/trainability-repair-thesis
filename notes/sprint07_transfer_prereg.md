# Спринт 07 — переносимость сброса actor

## Вопрос и выборка

Помогает ли сброс actor после повышения вероятности повторения предыдущего действия в Breakout MinAtar с 0,10 до 0,25? Действия сохраняют смысл. PPO с архитектурой cnn, стандартные настройки проекта. Шесть новых исходных seeds 100–105. Исходное обучение по 999424 шагов среды (976 обновлений по 1024 шага), без промежуточных смен задачи. История обучения — единица независимости. Нет отбора по исходному return.

Из конечного состояния каждой истории стартуют два повтора каждой из двух веток. В одной сохраняются веса, в другой actor возвращается к исходной инициализации той же истории. Общие веса тела и critic, одинаковые свежие состояния Adam и одинаковый бюджет 131072 шага на ветку. Среды создаются заново. Парные env и PPO seeds зависят от истории и номера повтора, а не от ветки.

## Исход и анализ

AUC считается как среднее из четырёх средних episode return в последовательных окнах по 32768 шагов. Эпизоды учитываются по моменту завершения. Основной контраст — reset минус keep. Сначала усредняются два парных контраста внутри каждой истории, затем строится двухсторонний 95% t-интервал по шести историям. Порог практически значимого выигрыша +0,1. Нижняя граница строго выше +0,1 означает подтверждение в этой постановке. Верхняя граница строго ниже +0,1 означает отсутствие подтверждения выигрыша заданной величины с интервалом ниже порога. Иначе результат неопределённый. Пустое окно — техническая ошибка. Расширение выборки после просмотра данных не предусмотрено.

Отдельно описываются return и энтропия политики на старте, return после обучения и разброс по историям. Оценка использует 30 парных эпизодов с отдельными seeds. Сравнение оценивает эффект всей процедуры сброса после изменения динамики. Одновременно изменены траектории исходного обучения и вид смены. Вывод о специфичности эффекта для изменения динамики требует отдельного контроля с неизменной средой.

## Технический протокол

Однопоточный CPU на worker, не более двух workers. В каждом научном запуске телеметрия L2 на 0, каждые 64 итерации и в конце, L3 на 0, середине и конце. Полные checkpoints перед первым и последним обновлениями и начальные веса сохраняются отдельно. Для сохранения θ/Adam/RNG восстанавливается последнее обновление и проверяется побитовое совпадение. Зафиксированы SHA программы, протокола, конфигов, артефактов, версии окружения и seeds. Выходной каталог `runs/causal-trainability/sprint07_transfer_v1`.

Калибровка на независимом от новой выборки seed 0 с архивным развитием для веток. Три режима — исходное обучение на 0,10 и обе ветки на 0,25. Два прогрева по 4 итерации и три последовательные пары logging on/off, off/on, on/off. Бюджет каждой измеряемой ветки 131072 шага, равный научной ветке. Для режима исходного обучения калибруется 128-итерационный префикс с тем же интервалом L2 и той же частотой L3 относительно горизонта. Затраты на checkpoints, стартовую строку, обучение и закрытие телеметрии включаются в таймер. Проверяются побитовые weights/Adam/PPO RNG, rollout и неизменность глобального torch RNG. PASS если по каждому режиму mean и median overhead ≤5%. Исходный return в калибровке не служит критерием запуска. При техническом FAIL научный запуск ждёт исправления и отдельной калибровки.
