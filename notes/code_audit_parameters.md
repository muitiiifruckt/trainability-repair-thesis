## 2. Primacy Bias: reset не является одним универсальным оператором

В Appendix B, Fig. 9, уже сравниваются optimizer-only, parameters-only и standard resets на четырёх DMC tasks: optimizer-only почти не меняет результат, а parameters-only близок к standard. Это свидетельство для конкретного DrQ setting, не универсальный вывод о неважности optimizer. Paper также исследует actor/critic/target resets отдельно (Fig. 11). Поэтому factorial decomposition сама по себе не новая. [PDF, pp. 12–14](https://proceedings.mlr.press/v162/nikishin22a/nikishin22a.pdf).

**SAC, state observations — code-verified.** В [train_dense.py L107–111](https://github.com/evgenii-nikishin/rl_with_resets/blob/502ec52131471646cce871f9b7a94fac3cd2e651/train_dense.py#L107-L111) создаётся новый `SACLearner`. По [constructor L82–106](https://github.com/evgenii-nikishin/rl_with_resets/blob/502ec52131471646cce871f9b7a94fac3cd2e651/continuous_control/agents/sac/sac_learner.py#L82-L106) это новые actor, critic, target critic, temperature, Adam states, RNG и локальный update counter. Replay и текущий environmental trajectory живут вне learner и сохраняются. Default reset cadence: 200000 loop iterations; внешний training/evaluation clock продолжается. LR постоянный в inspected config, отдельного annealing scheduler здесь нет.

**DrQ, pixels — code-verified.** [train_pixels.py L141–175](https://github.com/evgenii-nikishin/rl_with_resets/blob/502ec52131471646cce871f9b7a94fac3cd2e651/train_pixels.py#L141-L175) сначала сохраняет online encoder, target encoder и целый critic encoder optimizer state, затем создаёт новый learner и возвращает эти три объекта. Получаются:

- сохранённые encoder weights и critic encoder Adam state;
- новые actor/critic heads и их optimizer states;
- новые target heads при сохранённом **старом target encoder**;
- новая temperature вместе с optimizer, новый learner RNG и локальный step;
- сохранённые replay, среда и внешние clocks.

Actor использует critic encoder; comment в коде поясняет, почему actor encoder optimizer не копируется. В [DrQLearner L99–128](https://github.com/evgenii-nikishin/rl_with_resets/blob/502ec52131471646cce871f9b7a94fac3cd2e651/continuous_control/agents/drq/drq_learner.py#L99-L128) видно пересоздание остальных состояний. Default cadence 25000 **loop iterations**, тогда как loop проходит `max_steps // action_repeat`: нельзя молча переводить этот параметр в frames или gradient steps. Это practically useful bundled intervention; считать его чистым weight-only repair некорректно.

**SPR/Atari — code-verified с отдельно отмеченной статической интерпретацией.** [reset_weights L522–565](https://github.com/evgenii-nikishin/rl_with_resets/blob/502ec52131471646cce871f9b7a94fac3cd2e651/discrete_control/agents/rainbow_agent.py#L522-L565) меняет online parameters по списку сохраняемых subtrees. Target не переписывается прямо внутри reset; обычный sync выполнен перед проверкой reset в [training loop L707–720](https://github.com/evgenii-nikishin/rl_with_resets/blob/502ec52131471646cce871f9b7a94fac3cd2e651/discrete_control/agents/rainbow_agent.py#L707-L720), следующий sync приходит по штатному cadence. Replay и exploration clock сохраняются. Optional `updates_on_reset` добавляет training work; paper-matched [SPR config](https://github.com/evgenii-nikishin/rl_with_resets/blob/502ec52131471646cce871f9b7a94fac3cd2e651/discrete_control/configs/SPR_with_resets.gin#L36-L39) задаёт четыре resets через 20000 steps, head/noise reset; default warmup и additional updates равны нулю.

Важная **статическая интерпретация**: optimizer subtree restoration выглядит неработающим для pinned Optax 0.1.2. [copy_params L59–69](https://github.com/evgenii-nikishin/rl_with_resets/blob/502ec52131471646cce871f9b7a94fac3cd2e651/discrete_control/agents/rainbow_agent.py#L59-L69) рекурсирует только через dict/FrozenDict. В [L549–557](https://github.com/evgenii-nikishin/rl_with_resets/blob/502ec52131471646cce871f9b7a94fac3cd2e651/discrete_control/agents/rainbow_agent.py#L549-L557) ему передаётся `_asdict()` внешнего MaskedState, но его `inner_state` — tuple от Adam chain: [Optax masked](https://github.com/google-deepmind/optax/blob/v0.1.2/optax/_src/wrappers.py#L262-L315), [chain](https://github.com/google-deepmind/optax/blob/v0.1.2/optax/_src/combine.py#L23-L54). Tuple считается leaf и заменяется новым целиком. Следовательно, по этой цепочке сбрасываются и encoder optimizer state/count, хотя encoder weights сохраняются. Runtime reproduction не проводилась; перед переносом SPR baseline требуется явно проверить его state tree.

## 3. Plasticity Injection: точная paper specification и overlap

Paper (§4) задаёт общий encoder и output `h_old(z) + h_new(z) − h_anchor(z)`: старый head и anchor parameters frozen, new head trainable; new и anchor изначально идентичны. **Все три ветви передают gradient в encoder**. Online и target networks получают intervention. Число trainable parameters сохраняется; total parameters и compute растут. Appendix B, Fig. 9, сравнивает RMSProp reset последних двух layers и перенос old-head optimizer state в new head; это не проверка произвольного Adam reset. Точное encoder-state/scheduler handling не code-verified. [PDF, §4–5, Appendix B](https://proceedings.neurips.cc/paper_files/paper/2023/file/75101364dc3aa7772d27528ea504472b-Paper-Conference.pdf).

**Главное пересечение:** Appendix B, p. 17, уже использует diagnostic **до** intervention: injection при `||w|| > 3||w_initial||`, где `w` охватывает encoder и head. Timing различается между играми; aggregate IQM совпадает с fixed injection @50M. Следовательно, claim «первый pre-repair selector» слишком широкий. Наше возможное отличие — prospective **multi-action** choice, честный held-out environment split и regret относительно intervention oracle. [Тот же PDF, Appendix B](https://proceedings.neurips.cc/paper_files/paper/2023/file/75101364dc3aa7772d27528ea504472b-Paper-Conference.pdf).

Наша интерпретация: output preservation контролирует немедленный behavioural jump, но не фиксирует будущую occupancy. В live RL свежие learning dynamics могут позднее менять exploration. Поэтому injection gain не доказывает, что все data/exploration причины исключены. Нулевой gain также не устанавливает единственную альтернативную причину.

## 4. On-Policy Study: что скрывается за названиями условий

Paper исследует несколько repairs и корреляции performance с diagnostics; Figure 3 использует агрегаты после длинных multi-round runs. Это близкий prior art для набора features, но не prospective выбор лучшего из нескольких actions на unseen checkpoint. [Paper, §4.2](https://arxiv.org/html/2405.19153v2).

**Общий optimizer reset при каждой task shift — code-verified.** [BaseTrainer L26–30](https://github.com/awjuliani/deep-rl-plasticity/blob/75f0d5af374e3b429316765928351234384ef261/shared/trainer.py#L26-L30) вызывает `model.adapt()`. В [PPOModel L59–70](https://github.com/awjuliani/deep-rl-plasticity/blob/75f0d5af374e3b429316765928351234384ef261/algos/ppo/model.py#L59-L70) fresh AdamW создаётся **после любого dispatch**, включая `none` и `soft-sp`. Поэтому baseline этого release — weights warm-start с optimizer reset на shifts, а не strict continuation всех states. Shift происходит до нового rollout; долгосрочного replay и target network в этом PPO path нет. Epoch clock продолжается, LR фиксирован, отдельный scheduler не найден.

**Weight decay и regeneration.** [Constructor L39–41](https://github.com/awjuliani/deep-rl-plasticity/blob/75f0d5af374e3b429316765928351234384ef261/algos/ppo/model.py#L39-L41) использует AdamW с `weight_decay=l2_norm`. Для default zero decay отличие от Adam в этом отношении отсутствует; `l2-norm` condition реализует decoupled decay, несмотря на README wording «normalizes». Regenerative term в [trainer L171–180](https://github.com/awjuliani/deep-rl-plasticity/blob/75f0d5af374e3b429316765928351234384ef261/algos/ppo/trainer.py#L171-L180) — коэффициент × **norm**, без возведения в квадрат. При port нельзя автоматически заменить его squared L2.

**S+P и reset-final.** [sp_module L287–292](https://github.com/awjuliani/deep-rl-plasticity/blob/75f0d5af374e3b429316765928351234384ef261/shared/modules.py#L287-L292) делает in-place `alpha*current + beta*fresh_initializer`; fresh draws берутся из generator соответствующего layer, не из произвольной isotropic Gaussian. `reset-final` задаёт alpha=0, beta=1 для policy/value heads; encoder не изменяется. Periodic variants наследуют общий optimizer reset на shifts. Soft-S+P вызывается после каждого minibatch optimizer step в [L192–197](https://github.com/awjuliani/deep-rl-plasticity/blob/75f0d5af374e3b429316765928351234384ef261/algos/ppo/trainer.py#L192-L197); между shifts moments сохраняются.

**Injection отличается от основной frozen версии Nikishin.** В [Injector L84–105](https://github.com/awjuliani/deep-rl-plasticity/blob/75f0d5af374e3b429316765928351234384ef261/shared/modules.py#L84-L105) old affine head остаётся trainable, new branch trainable, anchor output `.detach()` блокирует также encoder gradient через anchor. Выход в момент вставки совпадает, но active trainable head count и gradient в encoder отличаются. Повторная injection складывает старые affine heads в один. Unfrozen old-head варианты есть в ablations Nikishin, однако detach semantics основной specification не совпадает. Назвать два operators одинаковым baseline нельзя.

**Diagnostics — точные code definitions.** [modules.py](https://github.com/awjuliani/deep-rl-plasticity/blob/75f0d5af374e3b429316765928351234384ef261/shared/modules.py): `weight_m` — RMS по scalar parameters (L24–30); `weight_diff` — RMS разницы weights до/после epoch (L40–53). `dead_units` — mean zero activation entries последнего encoder output (L196–201, L266–271), **не** доля neuron identities, никогда не активировавшихся на dataset. `grad_norm` возвращается вызовом clipping до optimizer step. [Trainer L80–109](https://github.com/awjuliani/deep-rl-plasticity/blob/75f0d5af374e3b429316765928351234384ef261/algos/ppo/trainer.py#L80-L109) логирует эти значения после update; weight_diff включает внутренние mutations. Для pre-repair selector требуется независимый common probe до dispatch.

Дополнительные replication pitfalls этого release:

- [Runner L168–170](https://github.com/awjuliani/deep-rl-plasticity/blob/75f0d5af374e3b429316765928351234384ef261/shared/runner.py#L168-L170) мутирует один config между conditions; отсутствует reset к базовому dict. All-conditions invocation может переносить предыдущие adapt/activation/regularization flags. Single-condition CLI selection [train.py L34–40](https://github.com/awjuliani/deep-rl-plasticity/blob/75f0d5af374e3b429316765928351234384ef261/train.py#L34-L40) избегает этого. Это finding о runner, не доказательство происхождения paper results.
- ReDo port в [modules.py L306–321](https://github.com/awjuliani/deep-rl-plasticity/blob/75f0d5af374e3b429316765928351234384ef261/shared/modules.py#L306-L321) не сбрасывает bias/optimizer; outgoing zeroing зависит от совпадения типов соседних modules. В branched policy/value graph нельзя считать его без проверки canonical ReDo.
- `save_freq` сохраняет metrics/config, не полный train state: [runner L183–214](https://github.com/awjuliani/deep-rl-plasticity/blob/75f0d5af374e3b429316765928351234384ef261/shared/runner.py#L183-L214). Для clone experiment нужен наш full checkpoint serializer.

## 5. Минимальный набор для нашего эксперимента — предложенный дизайн

Следующие specifications — наши operational choices, а не утверждение, что авторы реализовали именно их.

1. **Strict continue:** клонировать weights, optimizer buffers/counts, target, replay, clocks и scheduler; ни одно из них не обновлять при dispatch.
2. **Optimizer-only:** те же weights/data/target/clocks; reset точно выбранного optimizer state. Сохранение global LR schedule отдельно от сброса Adam count обязательно записать. Juliani-style reset-on-shift — отдельный literature baseline.
3. **Head-only и head+optimizer factorial:** fresh head weights одного initializer draw; заменять значения существующих Parameters, чтобы optimizer продолжал ссылаться на правильные объекты. В weight-only arm сохранять old moments/counts намеренно; joint arm reset тех же head states. Target handling вынести в явный фактор, а не делать скрытый sync.
4. **Paper-specified injection:** frozen old/anchor parameters, fresh trainable residual, общий trainable encoder, без detach encoder inputs; initial online и target outputs сохраняются отдельно. New-head optimizer state fresh, encoder state сохранён — это наш выбранный port policy, пока author code отсутствует. Добавить вариант с copied old-head state как literature ablation. Название: paper-specified port, не exact author-code reproduction.
5. **Soft-S+P:** in-place alpha/beta update после каждого minibatch step, свежий initializer draw, moments сохранены; отдельно указать, есть ли task-shift optimizer reset. Beta=1e-6 и alpha=1−beta — reference condition из on-policy source, не результат tuning для нашей среды.
6. **Diagnostic policy baseline:** norm-threshold inject/continue с порогом 3× initial norm. Взвешивание layers, включение biases и момент измерения явно зафиксировать: paper не даёт полностью code-verified convention. Порог и method hyperparameters не подбирать на held-out environments.

До обучения проверить invariants: clone identity; optimizer parameter references после repair; exact parameter/state diff mask; отсутствие роста trainable count в frozen injection; output preservation online и target; одинаковые data/target rules в controlled arms. Diagnostics должны измеряться на одинаковых states **до** action; последующие показатели доступны только для анализа механизма. Учитывать real updates и wall-clock overhead injection/S+P, не только число environment frames.

Самое полезное научное отличие после audit: заранее выбирать **между** совместимыми, явно описанными interventions и показывать перенос выбора на held-out environments. Сам факт checkpoint branching, optimizer/weights ablations и diagnostic-triggered injection уже имеет прямые предшественники.
